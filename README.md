## Folder Details

### 1. `SpikeGPT/`
- Contains the original source code used to define and train the SNN-based language model, including the model structure (`src/model.py` with Spiking RWKV/RFFN architecture), training scripts (`train.py`, `run.py`), CUDA optimizations (`cuda/`), and the SNN implementation kernel (`spikingjelly/` folder) referenced from the original paper.
- **Note on code state:** This folder currently acts as an original copy downloaded from GitHub. During practical experimentation (e.g., training on Kaggle with new datasets), the source code files (such as `model.py` or configuration files) are continuously modified and intervened. Specifically, this involves tuning the code to enable or disable the `headqk` mechanism. Due to the flexibility required during these experiments, the actual training phase generates multiple variant versions of the model architecture, rather than sticking to the single fixed structure currently present in this folder.

### 2. `Notebooks/`
Contains all the Jupyter notebooks for the project:
- **`trial`**: Evaluates 2000 samples generated by the LLM to ensure semantic correctness and data integrity before applying data augmentation for model training.
- **`demo`**: Contains the backend source code for the demonstration (hosted on Kaggle to run up to 6 models simultaneously).
- **`eval`**: Evaluates the performance scores of the SpikeGPT model after training.
- **`gpt2-eval`**: Evaluates the performance scores of the GPT-2 model after training.
- **`gpt-medium/small-finetuning`**: Used for fine-tuning the GPT-2 models.
- **`headqk`**: Used for training the SpikeGPT model.
- *Note:* SpikeGPT was trained multiple times across several variants (with and without `headqk`) by calling a clone of the GitHub branch to train directly on Kaggle. The base model structures are located in the `SpikeGPT/` folder.

### 3. `demo/`
- Contains the **Frontend** source code for the web demo application. 
- It operates by running the Backend on Kaggle, exposing an API via ngrok. The local Frontend simply calls this API, allows the model to process inference, interacts with the Supabase database, and returns the output to be displayed on the Frontend.
- The **Backend** code implements the mechanisms described in the LLM tool-calling references.

### 4. `Evaluations/`
- Contains the complete results from 6 evaluation runs on the 5k-sample test dataset.
- Includes confusion matrices, notebook execution results, result charts, and detailed prediction results for each individual sample.

### 5. `Documents/` (or `bao-cao-latex/`)
- Contains PDF files of the presentation slides, final report, original reference paper, and other preparation contents.

### 6. `data/`
- **`Agent_data_LLM.json`**: 2000 one-turn conversation samples generated using Gemini + ChatGPT, which were then validated to retain only standard-quality samples.
- **`train/valid_tool_data.jsonl`**: 56,000 and 7,600 samples respectively, generated using Data Augmentation techniques based on the original 2000 validated samples.
- **`test_ood_data`**: 5,000 samples used to formally evaluate the models after training completes.

### 7. `preprocessing/`
- **Main function:** Converts raw text data files from the `.jsonl` format into binary format (`.bin`) and index files (`.idx`) to optimize data loading and processing speeds during language model training.
- **Tool components:** Contains `preprocess_data.py` along with tokenizers (`20B_tokenizer.json` and `rwkv_vocab`) to standardize input data for the RWKV and SpikeGPT architectures.
